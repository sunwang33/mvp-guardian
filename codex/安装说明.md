# MVP Guardian（MVP 守门员）— Codex 安装说明

当前版本：**v2.3**（写码前检查改为状态触发：进入「开发中」后的第一条回复先输出清单，再执行任何命令/文件写入/依赖安装；v2.2 分档机制全部保留）

MVP 开发守门员 skill：在 vibe coding 过程中辅助并监督 MVP 思路（新产品开发 / 已有产品加拓展功能 / 小任务增量 / 可行性快速验证）。

核心信念：**先把闭环跑通，再谈完美。**

设计定位：**硬门槛守门**——先分档（快速验证 / 增量 / 完整）并说出判断，再走阶段门禁链（三问 → mvp-plan 确认 → PRD 确认 → UI 结构确认 → 写码前检查清单），任何一道未过禁止写生产代码；阶段授权不传递（一次点头只覆盖被呈现的那一个阶段）；计划落盘到项目根目录 `mvp-plan.md` 并维护阶段状态机；需求模糊时进入 grill 式追问（复述时区分「用户说的」与「我的假设」）。

## 目录内文件

| 文件 | 安装位置 | 作用 |
|------|---------|------|
| `codex/SKILL.md` + `references/` + `agents/` | `~/.codex/skills/mvp-guardian/` | 技能本体，按描述自动匹配触发 |
| `codex/prompts/mvp.md` | `~/.codex/prompts/mvp.md` | 手动召唤命令：会话里输入 `/mvp` |
| `codex/AGENTS.md` | 某个项目根目录（可选） | 项目级强制注入，不依赖 skill 触发 |

> 也可以直接在仓库根目录执行 `bash scripts/deploy.sh` 一键完成以上全部部署。

## 安装步骤

### 1. 安装技能本体

```bash
# 方式 A：直接克隆到技能目录（推荐，之后 git pull 即更新）
git clone https://github.com/sunwang33/mvp-guardian.git /tmp/mvp-guardian-src
mkdir -p ~/.codex/skills/mvp-guardian
cp /tmp/mvp-guardian-src/codex/SKILL.md ~/.codex/skills/mvp-guardian/
cp -r /tmp/mvp-guardian-src/references ~/.codex/skills/mvp-guardian/
cp -r /tmp/mvp-guardian-src/codex/agents ~/.codex/skills/mvp-guardian/

# 方式 B：从下载包（mvp-guardian-codex-share-v2.3.zip）解压后
# Windows (PowerShell)
Copy-Item -Recurse mvp-guardian "$env:USERPROFILE\.codex\skills\"
# macOS / Linux
cp -r mvp-guardian ~/.codex/skills/
```

装好后，在 Codex 里说「mvp」「新功能」「开始开发」「做一个 XX 网站」等，技能会按描述自动匹配。

### 2. 安装 /mvp 命令（推荐，手动召唤入口）

```bash
# Windows (PowerShell)
New-Item -ItemType Directory -Force "$env:USERPROFILE\.codex\prompts" | Out-Null
Copy-Item mvp.md "$env:USERPROFILE\.codex\prompts\mvp.md"

# macOS / Linux
mkdir -p ~/.codex/prompts && cp mvp.md ~/.codex/prompts/mvp.md
```

之后任何 Codex 会话输入 `/mvp` 即可启动完整守门员流程。

### 3.（可选）项目级 AGENTS.md

如果想让某个项目**强制注入**监督规则（不依赖 skill 触发匹配），把 `AGENTS.md` 复制到该项目根目录；项目已有 AGENTS.md 则做追加合并。不推荐放进全局 `~/.codex/AGENTS.md`（非开发任务也会被注入）。

## 使用建议

- **新项目**：进项目目录 → `/mvp` → 守门员先分档（多半是完整档），从三问开始走门禁链
- **给已有项目加功能**：`/mvp` → 选「拓展功能 MVP」模式，三问针对该功能
- **已有产品的小改动**：`/mvp` → 守门员会问是否走**增量档**（复用已有计划，只补本次变化，省掉 PRD 与 UI 门禁）
- **只想验证「能不能做」**：`/mvp` 或直接说「能不能用 XX 做 YY」→ 走**快速验证档**（不落盘、不出 PRD，半天内给出「能做 / 做不了 / 能做但很贵」的结论）
- **mvp-plan.md** 会落在项目根目录，跨会话可追溯；验收对照它的完成标准逐条核对，通过后会自动记一条试用反馈
- **授权要一阶段一阶段给**：批准计划 ≠ 批准 PRD ≠ 批准 UI，守门员不会拿一次点头当万能通行证

## 与其他技能的协同

- UI 结构设计阶段：若装有 `design-taste-frontend`（taste-skill 仓库）或 `frontend-design`，会自动调用以避免页面模板化；没有也不影响，内置 5 项清单兜底
- 本技能自包含，不依赖其他技能即可完整运行

## 反馈

实测中如发现 Codex 不遵守某条规则（如跳过写码前检查清单、顺手加功能），记录具体现象反馈给作者，用于加强措辞。
